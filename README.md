# EduLink

## Журнал занятия и рейтинг дисциплины (PostgreSQL)

У занятия в кабинете преподавателя есть ссылка «Журнал занятия». Преподаватель отмечает
посещение (присутствовал, опоздал, отсутствовал, уважительная причина), видит автоматически
рассчитанные баллы тестов и выставляет итоговый балл 0–100 с точностью до двух знаков.
Комментарий к оценке виден студенту. Посещаемость доступна во время занятия, итоговые баллы —
после времени окончания или отметки «Проведено». Досрочно завершить занятие можно в журнале,
предварительно закрыв открытые тесты.

Результаты тестов обновляются в журнале каждые 5 секунд. Баллы свободных ответов подтягиваются
после проверки преподавателем. Итоговый балл заполняется вручную и не меняется автоматически
при пересмотре теста. Пустая оценка отличается от выставленного нуля.

Рейтинг дисциплины = сумма итоговых баллов за завершившиеся неотменённые занятия.
Баллы тестов повторно не прибавляются. Равные суммы дают одинаковое место (1, 1, 2).
Без выставленных оценок место не определяется. Исправление или снятие оценки автоматически
меняет сумму при следующем запросе рейтинга. Записанные оценки сохраняются при переводе студента
в другую группу. Журналы защищены от перезаписи устаревшей версией.

Преподаватель открывает «Рейтинг по дисциплине» в кабинете или из журнала; доступен экспорт CSV.
Студент открывает «Мои баллы и рейтинг»: видит только собственные оценки, посещения и место,
без оценок и комментариев одногруппников. Администратор может читать журналы и рейтинги.
Журнал с оценками и аккаунт с оценками нельзя удалить — используйте отмену занятия/блокировку аккаунта.

Таблицы: `lesson_journals`, `lesson_marks`. API: `/api/journal/lessons/:id`,
`/api/journal/lessons/:id/complete`, `/api/journal/courses`, `/api/journal/courses/:id`.
На свежей отдельной тестовой базе с суффиксом `_test` задайте `TEST_BASE_URL` и `TEST_DATABASE_URL`:
`node --test --test-concurrency=1 test/journal.test.js test/learning.test.js test/schedule.test.js`.


## План занятия и тестирование (PostgreSQL)

В кабинете преподавателя у занятия доступна ссылка «План и тестирование».
План содержит цель и упорядоченные этапы: название, описание, длительность и связанный тест.
Созданные тесты выбираются в поле «Тест этапа» редактора плана.

Преподаватель задаёт количество заданий (1–50), время одной попытки (1–240 минут),
формулировки и варианты ответов. Типы: одиночный выбор, множественный выбор и свободный текст.
Выбор проверяется автоматически: 1 балл за полное совпадение, 0 за неверный или неполный ответ.
Свободный ответ оценивается преподавателем в 0 или 1 балл через «Ход выполнения → Ответы и оценка».

Тест имеет состояния «Черновик», «Открыт», «Завершён». После открытия содержание неизменяемо.
Каждому студенту своей группы доступна одна попытка. Таймер начинается на сервере при старте,
не сбрасывается при перезагрузке страницы; ответы автоматически сохраняются во время ввода.
По истечении времени фиксируются ранее сохранённые ответы. При потере связи несохранённые
изменения не попадают в результат. Преподаватель может завершить тест сразу для всех.
Журнал показывает не начавших, выполняющих и завершивших студентов, время начала и окончания,
причину завершения и баллы. Ключи правильных ответов не передаются студентам.

Таблицы `lesson_plans`, `lesson_tests`, `test_attempts` создаются при запуске без изменения
существующих занятий. Фоновая проверка закрывает истёкшие попытки каждые 2 секунды;
временем окончания записывается точный дедлайн. После перезапуска сервера проверка возобновляется.
Планы защищены от сохранения устаревшей версии. Тесты с результатами сохраняются для истории.

Проверка: запустите отдельный сервер на свежей тестовой базе с именем, заканчивающимся на `_test`.
Задайте `TEST_BASE_URL` и `TEST_DATABASE_URL`, затем выполните
`node --test test/learning.test.js test/schedule.test.js`.
Тесты создают данные; использовать только отдельную тестовую базу.


EduLink — учебная платформа для организации учебного процесса со студентами. Основные роли: **преподаватель**, **студент**, **администратор**.

## MVP

- администратор управляет учетными записями, ролями, статусами, поиском, фильтрами и CSV-экспортом;
- преподаватель видит профиль и свои занятия, группы и дисциплины;
- студент видит профиль, учебную группу и расписание;
- преподаватель и студент могут подключиться к общему WebRTC-занятию;
- базовые учебные сущности хранятся в SQLite: accounts, teacher_profiles, student_profiles, courses, lessons.

## Запуск

Требуется Node.js 22.5 или новее (проверьте `node --version`). Версия для nvm указана в `.nvmrc`.

```bash
npm ci
npm start
```

Откройте http://localhost:8000. Без `DATABASE_URL` запускается деморежим SQLite.
Управление группами и дисциплинами требует PostgreSQL.

### PostgreSQL — полный режим

1. Подготовьте существующую пустую PostgreSQL-базу и пользователя с правами создания таблиц.
2. Скопируйте `.env.example` в `.env` и задайте `DATABASE_URL`.
3. Выполните `npm run start:postgres` (или `npm start`, который выберет PostgreSQL автоматически).

`.env` загружается из папки проекта; переменные окружения имеют приоритет.
Таблицы и демонстрационные данные создаются при первом запуске. Перенос данных
из SQLite автоматически не выполняется. Проверка PostgreSQL-сервера: `GET /health`.

Явный запуск деморежима: `npm run start:sqlite`. Эти режимы используют разные базы.
Для регистрации и восстановления пароля настройте `RESEND_API_KEY` и `EMAIL_FROM`.
Только для локальной разработки можно включить `ALLOW_DEV_OTP=true`.
Параметры TURN в `.env.example` необязательны для запуска сервера.

### Если сервер не запускается

- Ошибка версии Node.js: установите Node.js 22.5+ и заново откройте терминал.
- Не найден модуль `pg`: выполните `npm ci` в папке проекта.
- Ошибка PostgreSQL: проверьте `DATABASE_URL`, доступность базы и права пользователя.
- Порт занят: задайте другой `PORT` в `.env`.

## Управление расписанием (PostgreSQL)

Войдите администратором и откройте «Расписание». Доступны создание,
редактирование и перенос занятий, копирование на другую дату, отмена,
отметка о проведении, удаление с подтверждением и экспорт отфильтрованного списка в CSV.
Поиск и фильтры: период, преподаватель, группа, дисциплина, статус.
Даты отображаются и вводятся в часовом поясе браузера; в базе сохраняются как TIMESTAMPTZ.
Верхняя дата фильтра включается целиком. Пересечения проверяются для группы и
преподавателя; смежные интервалы разрешены, отменённые занятия время не занимают.
Возврат отменённого занятия в расписание доступен через редактирование и снова проверяет пересечения.

Изменения видны в кабинетах преподавателя и студента после обновления страницы.
Групповые видеокомнаты остаются отдельным этапом: существующий WebRTC использует общую комнату.

API: `GET/POST /api/admin/lessons`, `GET/PUT/DELETE /api/admin/lessons/:id`.
Для интеграционных тестов запустите отдельный сервер с отдельной тестовой PostgreSQL-базой,
затем задайте `TEST_BASE_URL` и выполните `node --test test/schedule.test.js`.
Тесты используют демо-аккаунты и создают/удаляют тестовые занятия; не запускайте их на рабочей базе.

## Локальная почта для разработки

Запустите Mailpit с SMTP на `127.0.0.1:1025` и веб-интерфейсом на `127.0.0.1:8025`.
Задайте в `.env` и перезапустите EduLink:

```dotenv
MAIL_PROVIDER=smtp
SMTP_HOST=127.0.0.1
SMTP_PORT=1025
SMTP_SECURE=false
EMAIL_FROM=EduLink <noreply@edulink.local>
ALLOW_DEV_OTP=false
```

Письма регистрации и восстановления пароля будут доступны в Mailpit, без отправки во внешнюю почту.
Поддерживаются оба сервера проекта. Внешний SMTP также поддерживается через `SMTP_USER` и
`SMTP_PASSWORD`; для него требуется TLS. Существующий Resend доступен при `MAIL_PROVIDER=resend`.

Студент: `elena.smirnova@edulink.local` / `StudentDemo123!`

В production демо-пароли необходимо отключить и передавать секреты через защищенное хранилище.

## Предметная модель

- `accounts` — пользователи и роли;
- `teacher_profiles` — кафедра, должность, телефон;
- `student_profiles` — номер студента и учебная группа;
- `courses` — дисциплины;
- `lessons` — занятия, преподаватель, группа, время и видеокомната.
